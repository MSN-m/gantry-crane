# 港口吊装游戏：未来规划归档

更新：2026-10-16。记录讨论结论与候选方案，不等于全部批准开发。

**“一键归档”的约定：整理讨论、决定和未来规划，写入项目文档；不指归档聊天。** 后续沿用此含义。展示规划时优先使用简短表格和稳定编号。

## 1. 产品方向

| 主题 | 当前方向 |
|---|---|
| 定位 | 个人开发的小体量竖屏手机游戏，玩家当吊车操作员；考虑微信小游戏、TapTap。 |
| 主流程 | 从卡车抓箱，装入船舱；保留装船成果，追求排列、填满和整船离港的满足感。 |
| 常规模式 | 小丑牌式构筑与高分闯关：通过货物、摆放和规则搭配，跨越逐渐提高的分数门槛。具体构筑规则待定。 |
| 每日挑战 | 羊了个羊式每日固定高难关：共用货单与初始布局，方便交流解法和成绩。难度、补救与排名规则待定。 |
| 两种模式关系 | 当前讨论方向是共用核心玩法；避免为个人开发扩张成两套独立游戏。 |
| 商业前提 | 以广告变现为主要考虑；具体接入、收益与广告位置未确认。 |
| 设计顺序 | 先确认完整版，再反推教程、解锁顺序和难度提升。 |

## 2. 已认可的核心设计

下表沿用[完整版取舍记录](harbor-full-version-decisions.md)的编号，避免后续讨论混淆。

| 原编号 | 主题 | 结论 |
|---|---|---|
| 2 | 操作 | 点击目标自动移动、对准；到位后手动确认抓取或落箱，自动完成升降。 |
| 3 | 视角 | 假3D、驾驶舱固定向下看；吊具悬挂点随驾驶舱移动，地面相对移动。最终支持点击切换多列。 |
| 5 | 船舱 | 多列、有限层高；预装箱形成地形，使摆放顺序与预留空间产生后果。 |
| 7 | 送货 | 卡车自动按顺序进场，玩家不能随意重排货单。预告数量另定。 |
| 9 | 基础积分 | 不同尺寸按标准格数计分；重复搬运不能刷分。 |
| 14 | 完成反馈 | 展示装载成果、结算、切换下一片船舱，整船完成后离港。 |
| 15 | 声光触感 | 灯装在吊具上：空载绿色，载货黄色闪烁；机械音效、可关闭的轻振。 |
| 16 | 长期挑战 | 个人纪录、关卡评价、每日固定货单与成绩比较；细节随模式确定。 |
| 17 | 场景变化 | 不同船型、港口和昼夜，优先保证箱位清晰可读。 |

吊具是抓取集装箱的框架。驾驶舱不跟着起升上下运动；起升改变吊具与货物离镜头的距离。当前原型先验证单列前后移动与升降，多列属于最终规划。

## 3. 货物与现场规则

### 货物属性

| 属性 | 状态 | 设计作用 |
|---|---|---|
| 颜色 | 保留 | 形成直观的组合与计分基础；具体组合未定。 |
| 目的港标识 | 已认可 | 卸货先后与同色聚集可能冲突，增加选择。 |
| 尺寸 | 已认可 | 大中小箱带来连续空间、补缝与先后顺序问题。 |
| 特殊货物标签 | 已认可 | 让箱子承担不同装载条件，支持更多规则搭配。 |
| 独立“装载区域加成” | 已放弃 | 不另设牵强的船头、船尾等区域奖励层；不影响真实设施箱位限制。 |

尺寸暂按长度变化、宽度统一、不旋转；颜色数量暂按三色，均可继续调整。

### 码头日常因素

这里的1–6是现场因素编号，与完整版1–17不同。

| 编号 | 因素 | 状态与含义 |
|---|---|---|
| 1 | 重量与承载 | 待定。是否加入重箱在下、承载限制，需要评估复杂度。 |
| 2 | 目的港与卸货先后 | 已认可。装船时考虑之后的取箱顺序，避免把先卸箱压住。具体约束强度待定。 |
| 3 | 不相容危险货物隔离 | 已认可。用简化标签表达哪些货物不能靠在一起；具体距离与判定待定。 |
| 4 | 冷藏箱供电与监控 | 已认可。多个事先具备设施的固定箱位可放冷藏箱，形成预留、占位和腾挪问题。 |
| 5 | 双箱吊装 | 尚未决定。可作为两个匹配小箱一起吊的设备能力候选。 |
| 6 | 检查、解锁与固定 | 尚未决定。需避免增加重复点击工序。 |

冷藏箱位的理解：不是随意圈一个奖励区域，也不必只有唯一位置。船上提前准备了供电、通风及检修条件，玩家从多个合格箱位中选择。高层也可以有配套设施，游戏不需要模拟拉电缆。现实作业条件在游戏中简化表达。

## 4. 小丑牌结构如何对应

这是设计分析，**尚未全部确定接入**。

| 设计线 | 小丑牌 | 我们的对应与缺口 |
|---|---|---|
| 基础内容 | 扑克牌属性 | 集装箱颜色、尺寸、目的港、特殊标签。 |
| 当前选择 | 手牌、抽牌 | 当前来货与后续预告；如何影响未来货单待设计。 |
| 组合 | 对子、顺子等牌型 | 摆放组合；当前同色堆叠不足以支撑完整版。 |
| 持续规则 | 小丑牌 | 候选为“工单”等持续效果；这是核心缺口，需要改变摆放选择。 |
| 内容改造 | 改造牌组 | 候选为调整后续货单的颜色、尺寸、标签分布。 |
| 临时工具与升级 | 消耗牌、牌型升级 | 候选为一次性调度工具、升级某类装载组合。 |
| 资源与取舍 | 金钱、商店、槽位 | 局内资金、购买或替换工单、有限生效位；均待确认。 |
| 行动限制 | 出牌、弃牌次数 | 候选为搬运次数、腾挪额度、周转位；不照搬所有限制。 |
| 闯关压力 | 盲注、Boss | 分数门槛、合同条件与特殊限制；具体结构待定。 |

需要借鉴的是“货物—摆放—持续规则—资源选择”的联动。仅增加倍率数值，难以形成足够的构筑差异。

### 工单的候选职责

- **货单**：接下来送来什么箱子。
- **工单**：本局选择的持续规则，候选对应小丑牌。
- **合同**：这一关要达到的分数或任务目标。
- **设备能力**：改变操作能力，例如双箱吊装，未必都归入工单。

名称、效果、数量、生效槽位、获得与替换方式均待确认。应先用已认可的货物属性设计出能相互配合、也能相互冲突的效果，再决定资源与商店。

## 5. 积分与玩法：尚待决定

| 主题 | 已有基础 | 未决问题 |
|---|---|---|
| 积分结构 | 标准格基础分、不刷搬运分 | 是否分为基础分、加分、倍率、乘倍；结算顺序如何清楚展示。 |
| 摆放组合 | 同色堆叠方向 | 邻接、连续、整列等哪些值得保留；如何避免唯一最优摆法。 |
| 条件收益 | 目的港、危险品、冷藏箱规则 | 是硬性合法条件、合同目标还是奖励触发；不要全部叠成惩罚。 |
| 地形与支撑 | 预装箱、多列、尺寸变化 | 是否必须完整支撑、支撑面等高；空洞与跨箱如何处理。 |
| 腾挪 | 顶层重搬、有限周转位暂定 | 额度、代价、是否能解除死局。 |
| 货单预告 | 当前＋后续两件暂定 | 构筑模式与每日挑战是否需要不同可见信息。 |
| 失败补救 | 尚未确定 | 分数不足、无合法箱位等失败条件；撤销、重试与广告辅助边界。 |
| 单局结构 | 连续闯关方向 | 每关装多少、局间保留什么、何时选工单、何时结算。 |

广告候选是有限补救或额外选择，不宜每次吊装打断操作。这是建议，尚未确定；每日挑战若允许辅助，成绩是否区分也需讨论。

## 6. 当前原型与最终规划分开

原型位置：[harbor-operator](../prototypes/harbor-operator/README.md)。

| 当前已有 | 未来规划，尚未实现 |
|---|---|
| 手机竖屏假3D，巨轮密集背景箱、码头道路与卡车 | 多列交互船舱、不同船型与场景 |
| 三箱位、每位两层，六个等尺寸三色箱 | 大中小箱、预装地形、目的港与特殊箱规则 |
| 自动移动，手动确认抓放，自动升降 | 构筑工单、局内资源与选择、连续闯关 |
| 吊具绿灯／载货黄闪、轻振开关 | 每日固定高难挑战与成绩比较 |
| 每箱100、同色上下配对50、完成200；满分950 | 完整组合与倍率体系；现数值只作教程验证 |
| 落箱得分预览、撤销回滚状态与积分 | 顶层重搬、有限周转区与正式失败补救 |

原型开局需先移动一次才能操作的问题已修复。现有撤销不代表已确定完整版的腾挪规则。平台实际振动适配仍需单独验证。

## 7. 后续讨论顺序

1. 用颜色、尺寸、目的港、特殊箱设计一组具体工单，验证是否形成不同打法。
2. 确认摆放组合和积分结构，让收益能预判、结算能看懂。
3. 确定支撑、腾挪、货单预告与失败补救。
4. 确认常规模式的局间选择，以及每日挑战共享哪些规则。
5. 完整版确认后，再反推教程与难度提升。
