# 港口吊装游戏：未来规划归档

更新：2026-10-23。当前参数版本为 `phase3-v2`，已追加取消未放置持货功能。本文为当前规划入口；过程和依据见[10月21至22日讨论归档](harbor-session-2026-10-22.md)。

最新设计讨论见[10月23日工分与合约归档](harbor-session-2026-10-23.md)。持续规则卡已确认改称“合约”（原工单），局内资源暂名“工分”；尚未接入经济或替换原型旧称。
**“一键归档”指整理讨论、决定和未来规划并写入项目文档，不归档聊天，不自动实施未决功能。** 区分用户确认、已实现原型和临时参数；程序检查不能替代人工体验验收。

未来候选与未决细节以[想法与待决事项管理表](harbor-idea-backlog.md)为维护主表。后续相关沟通出现新想法或实质决定时，当轮同步条目、来源、状态与历史；本文件保留摘要。

## 1. 当前方向与状态

| 主题 | 当前记录 |
|---|---|
| 产品 | 个人开发的竖屏港口吊装游戏，以选货、空间摆放和工单构筑争取高分 |
| 平台目标 | 微信小游戏、抖音小游戏、TapTap普通小游戏；工程与三端上架步骤另有路线文档，未视为已完成接入 |
| 当前交付 | 网页可玩原型，三批需求已接入，等待真人试玩；不等于正式版已完成 |
| 主循环 | 四车一批，任选接货或永久放行，双周转车缓冲，有限来货，两阶段独立达标 |
| 构筑 | 两家无固有能力的货主、九类16张工单，每阶段开始前三选一，工单与成长跨阶段保留 |
| 评价 | 达标交付／高分交付两级，不强制满载、零放行或接收全部货物 |
| 当前难度 | 第一阶段2600、第二阶段3000，高分线8000；无工单单阶段最高2400，必须获得工单额外收益 |
| 商业化 | 免费游玩＋广告为规划方向；具体广告位置、奖励、触发与资质未在本轮核实或定案 |

## 2. 当前核心规则

编号与本轮归档对应，后续沟通可引用。

| 编号 | 主题 | 当前规则 |
|---|---|---|
| R01—R03 | 来货 | 四车2×2同时可选；取空一车不补位，批次全部处理完后自动换批，也可手动放行余货；受控随机货单生成后固定，无后续预告 |
| R04—R05 | 周转与锁定 | 两辆周转车每辆一箱，不堆叠；货物跨批跨阶段保留；已正式落船的布局不能撤销或搬回 |
| R06—R08 | 阶段与机会 | 先船尾第一列，再第二列；每阶段六批共24车，当前原型两阶段共48车；达标可主动切列，旧列封存、剩余来货永久放弃 |
| R09 | 结束 | 周转车有货时先提醒，可返回当前列摆放或放弃后结算；不能回旧列修改 |
| R10—R14 | 工单 | 货主不自带能力；每阶段三选一；卡片可看规则、调整顺序；按次结算且成长一次；旧列布局继续参与适用的新效果，历史分不重算 |
| R15 | 评价 | 两阶段都达标为达标交付；再达到整船高分线为高分交付，三星留后 |
| C01—C03 | 画面与移动 | 固定高位假3D视角，镜头拖拽暂关；轻点实物自动按X／Y移动，到位手动确认抓放，升降自动，取消附加摇摆和自动转头 |
| C04—C05 | 正常返回 | 成功落船／临停并升至安全高度后，吊具与镜头一起回开局原点；单独移动、抓取不返回 |
| C06—C10 | 取消持货 | 已吊起未放置时可取消，包括移动途中；回本次来源下降放回，再安全提升并留在来源；不计分、不触发工单、不切批、不结束；下降与提升中锁定 |

取消只针对当前持货，绝不恢复“船上箱子可以无限撤销”。从周转车重新抓取后，来源是该周转车，不是更早的来货车。

## 3. 当前计分与管理入口

- 基础：短箱50、长箱100；上下直接同色每半格接触＋25，左右不计。
- 满列额外＋200已按用户要求移除。它最初是原型自行补入的方案，不应再作为用户确认规则。
- 第一阶段2600、第二阶段3000为本轮实施参数，高分线8000仍待真人校准。阶段目标独立，前列超额不能抵扣后列。
- 工单细节以[工单管理表](harbor-work-order-registry.md)为维护入口，执行数值以[config.js](../prototypes/harbor-operator/config.js)为准。
- 当前候选剔除无法越过门槛的纯转色起手、边角专家＋纯转色组合；其他可行第二阶段组合仍保留转色协议。筛选算法是原型适配，不是永久通用解法。
- 本局结算可导出种子、参数版本、工单顺序、逐列分数、前台作业时间、装载／放行／周转／取消等统计与事件；重新开始前需自行导出。

工单管理目前是Markdown资料＋代码配置，不是后台，没有单卡启停按钮、热更新、权重／稀有度编辑或任意效果编辑器。
