# 港口吊装手机游戏：待讨论记录

本文保留早期讨论历史，其中“待讨论”“卸货”等表述不代表最新状态。最新综合规划与原型状态见 [未来规划归档](harbor-future-plan.md)，编号1–17的取舍见 [harbor-full-version-decisions.md](harbor-full-version-decisions.md)。当前方向为常规构筑闯关＋每日固定高难挑战，具体机制待确认。

记录日期：2026-10-14。计划下次讨论：2026-10-15。

## 2026-10-15 决定及原型更新

采用点击固定目标位置后自动移动、到位后手动确认抓取或落箱；确认后自动下降、锁定或释放、提升。移动中允许改选和停止，确认不提前缓存，作业期间禁止重复触发。空载绿灯、载货黄灯闪烁，接触时尝试轻振，提供振动开关。当前仍使用卸货流程验证交互；装船得分、不同尺寸和初始占用仍待后续验证。

## 吊车信号灯

用户希望增加清楚可见的状态提示：
- 空载时显示绿色。
- 吊起物品、处于载货状态时显示黄色闪烁。

下次讨论信号灯的位置、闪烁节奏，以及如何在驾驶舱固定俯视画面中清晰表达。

## 自动对准与自动升降

用户希望考虑是否自动对准，并自动上升、下降，以减少重复枯燥的操作。辅助范围尚未确定，暂不实施。

下次讨论：
- 哪些动作由玩家完成，哪些可以自动辅助。
- 自动对准的触发范围，以及抓取、落箱时的自动升降流程。
- 如何在降低重复操作负担的同时，保留操作员的掌控感与技巧空间。

## 讨论背景

定位为小体量手机游戏，考虑微信小游戏或 TapTap。当前原型是固定驾驶舱向下看的假 3D 场景，只有沿一列前后移动和吊具升降，上方为密集装箱的巨轮，下方为码头马路与卡车装卸位。

近期讨论的装船方向包括同色堆叠得分、不同长度的箱子、初始占用和等高支撑规则；这些仍是待验证方案，不代表全部已确定或已实现。
