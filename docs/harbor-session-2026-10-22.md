## 2. 已确认并已接入的玩法

| 编号 | 主题 | 最新规则 |
|---|---|---|
| R01 | 来货 | 四辆一批，2×2排列，都在吊具下方；玩家可任选接货数量和顺序，不要求全部接收 |
| R02 | 切批 | 当前批全部取完、持货处理完且动作结束后自动换批；也可手动下一批，未取货永久放行 |
| R03 | 随机供货 | 每局、每列生成受控随机货单，减少颜色／尺寸的规律重复；生成后固定，不因放行重抽，不展示后续来货预告 |
| R04 | 周转车 | 两辆独立周转车，位于来货区靠船侧；各放一只长箱或短箱，不堆叠，货物跨批跨阶段保留 |
| R05 | 布局锁定 | 正式落船后不可撤销、搬回或调整；周转取放不属于正式交付，不计分 |
| R06 | 两阶段 | 从船尾第一列开始，达到本列门槛后可手动切到第二列；旧列布局与已得分封存，超额分不抵扣新列门槛 |
| R07 | 有限机会 | 每阶段独立六批、每批四车，共24辆；两阶段最多48辆。切阶段永久放弃当前阶段剩余来货，周转货物带入下一阶段 |
| R08 | 非满载结算 | 不强制满载或接收全部货物；来货耗尽后仍可处理周转货；两阶段都达标才算通过，整船总分另用于高分评价 |
| R09 | 余货提醒 | 各种准备结束的情况，只要周转车有货，就提供返回当前列摆放或放弃并结算；不能因此返回旧列 |
| R10 | 货主 | 电力设备公司／医疗用品公司，均可有四色、长短箱；货主自身无能力，由工单赋予收益 |
| R11 | 工单获取 | 每阶段开始前一次三选一，包括第一阶段；已有工单及成长跨阶段保留，不重复取得同ID |
| R12 | 工单结算 | 先基础与上下同色，再从左到右处理工单；允许排序；复核只重复适用计分，不重复成长或制造新落箱事件 |
| R13 | 跨列构筑 | 旧列布局继续参与适用的后续效果；新收入记入当前阶段，既有历史分不重算；新工单不追溯发分 |
| R14 | 工单表现 | 以卡片供玩家检查规则，不给箱子加工单专属小标；可看详情、当前状态和上次落船效果 |
| R15 | 评价 | 先做“达标交付／高分交付”两级；暂不做三星，不额外要求零放行或满载 |

两阶段数量、六批额度、三层容量等属于当前原型口径，不应由此推定完整版所有关卡永远相同。

## 3. 镜头与操作：以本节最终规则为准

| 编号 | 主题 | 当前行为 |
|---|---|---|
| C01 | 默认画面 | 按用户参考截图采用高位俯视，尽量覆盖船舱、四辆来货车、双周转车与少量海水 |
| C02 | 查看方式 | 移除右侧船舶区／来货区按钮，镜头拖拽现已暂时关闭；轻点实物选位，工单卡仍可拖动排序 |
| C03 | 作业移动 | 点击后吊具自动按X／Y移动，对准后手动确认抓放，升降自动；镜头跟随，保持朝向，不叠加摇摆与强制转头 |
| C04 | 正常放置后 | 成功落船或临停周转车，升回安全高度后，吊具和镜头一起缓动返回开局原点（原型X=0、Y=52） |
| C05 | 单独动作 | 单独移动或吊起货箱都不返回原点，也不重置观察角度 |
| C06 | 取消持货 | 已吊起、未放置时可点“取消 · 放回来源”，或按Esc；闲置持货和移动途中均可发起 |
| C07 | 取消流程 | 带货返回本次抓取来源、下降放回、升回安全高度；完成后停在来源位置，镜头跟随，不额外回开局原点 |
| C08 | 来源判定 | 从货车抓起就回该车；从周转车重新抓起就回该周转车，不回更早的货车；已落船箱子不能取消 |
| C09 | 动作锁定 | 下降、提升、正常回原点及取消动画中不接受新取消；取消期间锁定新选位和切批／切列／结束 |
| C10 | 取消副作用 | 不计分、不触发工单、不成长、不推进接力或封顶；不自动换批／结束，不把放回周转车算作一次新临停 |

用户曾反馈晕动，并反复修订镜头行为。此前的自由拖拽、松手保持、每次抓放后回正、镜头独自回原点等均属过程方案，不能覆盖本节。取消未放置持货也不等于恢复“已落船布局无限撤销”。

## 4. 当前计分与临时参数

### 基础规则与明确移除项

- 短箱正式落船＋50，长箱＋100。
- 正下方同色按每处半格接触＋25；只算新产生的直接上下邻接，不算左右，不反复补发以前的奖励。
- 长箱两侧同色可＋50，一侧同色＋25；工单可改变颜色互认或追加收益。
- **满列额外＋200已移除。** 这条最初由Codex自行补作原型参数，用户本轮明确删除，不能再作为已确认规则沿用。
- 抓取、移动、取消、周转取放不计分；放行不直接扣分，只减少可用货物与机会。

### 当前执行参数

| 项目 | 当前值 | 确认口径 |
|---|---:|---|
| 第一阶段目标 | 2600 | 用户要求提高到无工单额外收益不能通过；具体数值为对应原型实施参数 |
| 第二阶段目标 | 3000 | 同上，且高于第一阶段 |
| 整船高分线 | 8000 | 第三批模拟后试调值，仍待实际体验 |
| 无工单单阶段上限 | 2400 | 1800基础＋600上下同色，无满列奖励，严格低于两阶段目标 |
| 优先提货 | 每只符合条件箱＋20 | 当前工单参数，非最终平衡定案 |
| 长期客户 | 初始20，成长5 | 同上 |
| 长短接力 | 每档10 | 同上 |
| 边角专家 | 每次60 | 同上 |
| 追加报酬 | 每次25 | 同上 |
| 加急奖金 | ×1.5，逐次四舍五入 | 同上 |

封顶交付是工单：首次将一个完整箱位两侧堆到三层时，额外结算该箱位基础与同色；与已移除的整列装满奖励不同。复核与六种转色协议的边界详见工单管理表。

当前候选适配：首阶段不提供单独无法突破2400的转色协议；仅持有边角专家时，第二阶段也不提供仍无法达到3000的纯转色组合。转色未从工单池删除；这些限制是当前难度下的原型实施算法，不是用户逐项指定的永久投放规则。

以上“已完成”指网页原型已接入、实现时有程序检查记录。仍需确认的共同事项是实际玩法体验与真实设备表现；不因表格中的完成状态而自动通过人工验收。

工单管理尚不是后台：没有可点击的启停、配置发布、稀有度、权重编辑或任意效果编辑器。修改文档不会直接修改游戏。当前适合先维护Markdown与配置代码，是否做管理页以后再决定。

## 6. 已有验证与局限

- 基础规则回归记录覆盖1000种种子／2000列；工单规则覆盖16张及240种有序双卡组合。测试中包含正常候选不提供的组合，不代表这些组合能在当前流程取得或都可过关。
- 难度专项验证无工单完美满载仍不能通过、旧列超额不抵扣、候选限制及转色仍保留于可行组合。
- 取消专项覆盖四来货车与双周转车、闲置／移动中／反复取消、原来源恢复、动作与流程锁、无计分／成长、最后一车不误切批、来源占用不覆盖、取消后可正常交付。
- 实现时浏览器与触控仿真检查通过真实取放、三选一／排序、成功与失败、余货提醒、JSON导出、320px控件布局、取消来源标签／Esc及相机跟随，未捕获页面脚本错误。
- 当前phase3-v2策略样本各200局：普通持续装载136局通过、单路线与组合规划各200局通过；“普通”也有工单，只是不优化效果。模拟不代表真人通关率。
- 取消次数与起止事件进入本局记录，真实抓取次数保留；取消不记作一次新交付或临停。结果可导出版本、参数快照、种子、工单顺序、逐列统计与事件。
- 真实手机触感、误触、晕动、性能、阅读负担、整局时长和工单平衡尚未正式验收。用户认可过当前返回效果，不等于全面通过所有设备与玩法验收。
