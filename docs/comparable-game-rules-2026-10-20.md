# 港口吊装：同类游戏与可借鉴规则

调研日期：2026-10-20。

**重点参考更新（2026-10-20）：用户认可 [Cozy Cargo](https://vanova.itch.io/cozy-cargo)，原话“这个可以”“手感不错”。将其提升为优先研究对象，后续重点参考装箱操作与摆放反馈，并研究标签联动和得分构筑。此处手感评价来自用户体验，助手尚未试玩；具体好感来源仍待分析，不代表全部规则已批准采用。**

方法：使用 Codex-Game-Studios 的 `help` 做项目定位，借用 `brainstorm` 中的核心循环、玩家选择、同类参照与范围分析方法做定向研究。本次不重新立项，也不执行完整概念创作流程。

依据：[最新讨论](harbor-session-2026-10-19.md)、[未来规划](harbor-future-plan.md)、[当前原型](../prototypes/harbor-operator/README.md)。网页依据为官方商店、开发者发布页及游戏自身说明；未实际试玩，不据此宣称手感、留存或商业表现已经验证。下文“原作规则”指页面明确描述，“适配建议”是本项目的设计推导，全部尚待选择和验证。

## 1. 结论与研究顺序

找到了直接以集装箱装船为主题的游戏，也找到了与“有限空间＋摆放得分＋局内构筑”相近的游戏。没有据此确认某一款完整覆盖我们的双车选货、长短箱支撑、固定货单全部装完、持续工单构筑和每日挑战。

优先研究顺序：

1. **Cozy Cargo（用户认可，重点参考）**：用户反馈“手感不错”；优先研究装箱操作、摆放反馈、标签联动与得分构筑。
2. **Load the ship!**：最直接的装船顺序参考。
3. **Drop Duchy**：摆放规则如何接入跨关成长。
4. **Backpack Hero / Balatro**：空间组合与持续能力如何改变打法。
5. **Stow It**：后续真实货物约束的取材库。
6. **ISLANDERS / Port Cranes / Ship Loader**：分别补充空间得分、作业氛围与重量平衡。

当前设计判断：优先增加相互竞争的摆放理由。单独提高分数线、增加颜色或加快车流，不能保证形成新的决策。

## 2. 直接同类：装船、吊装与配载

| 游戏与来源 | 页面明确描述的原作规则 | 对我们适合借鉴的部分 | 适配边界 |
|---|---|---|---|
| [Load the ship! · Google Play](https://play.google.com/store/apps/details?id=com.ship.load) | 查看航线，把带目的地的货物放入箱堆；先到港的货物应保持可取，晚卸箱压在早卸箱上会造成阻塞。 | **装船为之后卸货服务。** 同色聚集得分与目的港顺序可以发生冲突，让同一颜色的箱子不再永远堆在一起最好。 | 已认可目的港方向，但具体强度未定。先用两站航线测试；不必立刻制作完整航行和手动卸货关卡。 |
| [Stow It · 游戏说明](https://arcade.binnacleai.com/stow-it/) | 重箱放低层；冷藏箱分配到供电位；危险品隔离；按目的港安排层序。 | **设施位是需要预留的资源。** 当前双车中的普通箱能拿同色分，但可能占掉随后冷藏箱需要的位置。 | 网站对现实规范的表述不作为本项目专业规范依据。借其游戏化规则；不要一次叠加重量、危险品、冷藏和目的港。 |
| [Port Cranes: Container Age · Steam](https://store.steampowered.com/app/2106720/?l=english) | 战役中限时把集装箱全部装上船；有恶劣天气、军用物资等挑战；快速模式提供计时挑战，场景有昼夜和天气变化。 | **同一作业循环用不同任务组织。** 对比普通作业、特殊货物班次，研究吊装现场感与完成整批作业的反馈。 | 更适合做题材与操作参照。计时压力会改变思考节奏，当前普通模式不宜直接照搬；天气先作为视觉变化候选。 |
| [Ship Loader · 开发者 Flazm 发布于 Kongregate](https://www.kongregate.com/en/games/flazm/ship-loader) | 磁力吊机把不同重量的货物放入船舱；错误配载可能使船倾覆。 | **重量让位置具有代价。** 放得进去不代表放得合理。 | 重量在本项目仍待定。若测试，先做可预测的左右重量差预览，避免直接引入复杂摇摆、掉落物理与精确操作惩罚。 |

上表前三项分别对应我们已有的目的港、冷藏供电和吊机题材方向；它们提供参照，不代表这些方向已经完成设计或批准开发。

## 3. 机制相近：空间摆放与构筑

| 游戏与来源 | 页面明确描述的原作规则 | 适配到港口吊装的建议 | 优先级 |
|---|---|---|---|
| [Cozy Cargo · 开发者 itch.io 页面](https://vanova.itch.io/cozy-cargo) | 在不规则箱体内摆放物品；标签之间有邻接收益和冲突；有加分、全局倍率、不同难度客户单与每日修正；每天之后可选新物品进入收藏；分数收据显示基础分、联动和倍率。页面标注开发中。 | **让货物属性参与组合。** 工单可改变某类箱子的得分关系；合同修正可改变当关优先级；落箱前后解释联动来源。 | 最高。结构接近，但开发中作品不能作为成功商业模式证明。 |
| [Drop Duchy · Steam](https://store.steampowered.com/app/2525310/) | 用不同形状与类型的方块摆放地形、建筑；相邻环境影响资源和单位产出；成行有奖励；通过卡牌、升级、市场和分支路线发展本局。 | **摆放决定收益，收益支持后续选择，选择再改变摆法。** 一关结束后获得工单或升级，让下一关的空间规划发生变化。 | 高。先验证摆放与工单循环；战斗、城建和多资源系统会扩大项目范围。 |
| [Backpack Hero · Steam](https://store.steampowered.com/app/1970580/) | 物品在背包中的位置影响能力；收集物品并组织空间，形成不同策略和联动。 | **每个空间关系都能成为能力条件。** 例如同一半列混色、完整箱位齐平、长箱上方两个短箱等可读的构型。 | 高。具体港口构型是我们的候选，不能写成原作已有规则；保持统一宽度、不旋转的已定方向。 |
| [Balatro · Steam](https://store.steampowered.com/app/2379780/Balatro/?l=english) | 有效牌型与独特小丑牌形成构筑，获取筹码越过盲注；不同工具可修改普通牌、升级牌型或提供持续能力；支持挑战和种子局。 | **分别设计基础组合、持续工单、组合升级和临时工具。** 工单要改变选货或摆放倾向，并能相互配合。 | 最高。固定货单仍需全部装完，不能照搬达标立即结束；当前也不必照搬全部卡牌类别。 |
| [ISLANDERS · Steam](https://store.steampowered.com/app/1046030/ISLANDERS/?l=english) | 建筑放置时按周围环境得分；获得足够分数可补充建筑并解锁新建筑；建筑用尽会结束。 | **眼前高分与未来空间价值竞争。** 玩家需要为后续高价值箱留空间，而不是只看这一箱的最大分。 | 中高。借鉴空间取舍；不照搬得分续货，以免违背固定货单。已放弃的独立船头、船尾区域加成继续不采用。 |

## 4. 最适合本项目的六条候选规则

以下不是原作规则复刻，也不是已确认需求。编号 R1–R6 仅用于后续讨论。

| 编号 | 候选规则 | 最小场景与玩家取舍 | 成本与检查重点 |
|---|---|---|---|
| R1 | **目的港层序**：两站航线中，早卸箱不应被晚卸箱覆盖。先试违规预警与最终合同评价；硬性禁止或重搬代价之后再比较。 | 红色早卸箱已在下方；红色晚卸箱叠上去能拿同色奖励，但会阻塞。放别处损失眼前分数，却保留卸货顺序。 | 中。颜色和目的港必须分开表示，例如颜色＋港口编号；先确认是否产生有趣冲突，再确定惩罚。 |
| R2 | **供电位预留**：仅在后续教学关加入冷藏货物，标出多个可用设施位。 | A车普通箱能凑同色；B车冷藏箱需要剩余供电位。预告还能看到后面一只冷藏箱，玩家要决定先取谁、空位留给谁。 | 中。检查实际可用容量与长短箱占位；出题时保证有解。普通箱能否占用设施位需明确，建议首轮实验允许。 |
| R3 | **互斥的组合偏好**：同色塔与混色列由不同工单支持；同一局可按构筑取舍。 | 同一红箱放左侧可补同色链，放右侧可完成三色列；持有的工单决定哪个更值。 | 低至中。与现有“联合运输”候选衔接。先做两套完整打法，避免某套在所有货单中都占优。 |
| R4 | **行为成长工单**：某种装载行为使工单逐渐增强。 | “短箱调度”：每个首次入舱短箱使之后短箱的额外分增加；“整层交付”：完成一层的指定组合后，提升后续合格组合的倍率。 | 中。成长按本关还是整趟航程保留需要单独确定。成长是有上限货量中的增益，不是无限触发；重搬不涨层，撤销完整回退。 |
| R5 | **组合升级＋有限持续位**：关间提供少量工单或升级选择，限制同时生效数量。 | 已有同色专精时，可以继续强化，或换入支持短箱补缝的规则；带来下一关的策略变化。 | 中至高。先实验“两张同时生效、关后选一项”的小规模结构，数量仅为实验起点；商店、资金与稀有度随后再评估。 |
| R6 | **可解释的收益预览**：同时显示这一箱的即时增分、工单触发、成长变化与规则风险。 | 落位前显示“本箱＋100；专色＋50；成长＋1层；会压住01港货物”。玩家能比较两个落点的后果。 | 低至中。已有精确增分预览可复用。成长带来的未来收益不要伪装成即时得分，非即时总收益也不能只靠本箱预览判断。 |

R1、R2属于已认可方向的具体化候选；R3延续现有工单探索；R4、R5涉及尚未确定的成长与跨关系统；R6扩展已有反馈。

## 5. 三个小实验，比一次加入全部规则更有价值

### 实验 A：同一货单，换工单后会不会换摆法

沿用现有颜色、长短箱和双车，制作同色专精与混色专精两个可切换方案。先不加目的港、冷藏、车流和商店。

观察：玩家是否改变保留哪辆车、先完成哪一列、为哪种尺寸留位；最优摆法和高分布局是否出现差异。如果只换了得分数字而摆法基本相同，工单还没有足够的策略作用。

### 实验 B：同色奖励与目的港顺序能否产生可读冲突

另做一个小货单，仅加入01／02两个目的港；保留一种工单，安排至少一次“同色高分但会压住早卸货”的选择。只测试装船规划，结算用可视化检查展示被阻塞的箱子。

观察：玩家能否在落位前理解后果；是否有机会选择较低即时分来改善整体结果；最后是否因为缺信息而无解。该实验不替换已确定的第一关。

### 实验 C：两张工单能否形成有取舍的联动

在实验 A 有效之后，增加一张成长工单和有限生效位。使用相同货单，比较单张效果与组合效果，检查组合是否鼓励新的装载顺序。

观察：玩家是否会为了成长投资而放弃即时高分；是否出现一套组合通吃；精确预览能否解释分数来源。优先验证几张规则的区别，再扩充内容数量。

## 6. 当前不建议直接搬入的内容

| 内容 | 原因 |
|---|---|
| 全程倒计时、移动抓取、复杂惯性同时加入 | 会让测试结果同时受操作压力和规划影响，难以判断工单是否改善核心乐趣。车流仍可独立试验。 |
| 装满就消除整层 | 清空货物会改变完整装船与目的港依赖；采用前需要重新确认产品方向。 |
| 达分立即封箱／离港、得分后无限续货 | 与固定货单全部装完的现有决定冲突。 |
| 供电、危险品、重量、港序同时作为第一关硬限制 | 教学信息过密；空间已经可能堵塞，增加约束前需要独立验证出题和补救。 |
| 无法完成的高风险合同 | Cozy Cargo 页面明确把可能不可完成的 VIP 单作为风险选择；本项目每日固定挑战更适合先保证可解，减少“输在货单”的感受。 |
| 直接复制大型内容库与多种经济资源 | 个人开发成本高，当前缺口是少数能互相作用的规则。 |

## 7. 下一步推荐

先做**实验 A：同色与混色两种工单，让同一批货物产生两种摆法**。通过后做两张工单的成长联动；目的港与冷藏分别放到独立后续关实验。

可采用的技能路线：`quick-design` 梳理被选中的小实验 → `prototype` 验证 → `playtest-report` 记录玩家选择 → 涉及分数与成长时用 `balance-check`。这些是后续建议，本次没有自动实施。
