# 港口吊装：2026-10-23丰富度、工分与合约讨论归档

归档日期：2026-10-23。本轮是设计讨论与资料整理，未修改游戏规则、实现局内货币、接入商店或统一替换原型界面的旧称。

**恢复讨论时先接本档第5节的问题，不将它视为用户已经回答。**

## 1. 为什么讨论新维度

用户认为当前丰富度不足，希望在保留现实感、不修改现有箱体与摆放逻辑的基础上，增加类似持续规则卡的新决策维度。

讨论中将现有内容拆为箱体属性、装载空间、持续规则构筑、货物流转与取舍四块；这是理解现状的分析口径，不是新增四套系统的决定。其中持续规则卡承担主要构筑，消耗道具和局内资源是候选补充。

| 讨论过的方向 | 当前结论 | 管理编号 |
|---|---|---|
| 同色对子、三色叠层、同色整垛等摆放牌型 | 用户不认可，担心破坏现实感；不改现有摆放去做牌型 | REJ-001 |
| 独立调度权系统 | 用户认为更适合消耗类道具；改由道具方向承接，不并行扩建权限系统 | REJ-002 |
| 消耗类道具 | 方向认可，具体道具及获取／持有／使用规则未确认 | ITM-001 |
| 货主预约、车型调度、精确调车、批次提前、临时周转许可 | 都只是候选示例，不随道具方向一并批准 | ITM-002至ITM-005、CAP-001 |
| 合同、额外委托、合作关系、设备服务 | 只是其他候选，未确认新增系统 | BUS-001至BUS-004 |

前两行分别对应REJ-001、REJ-002。各候选的来源、边界与状态维护在[想法库](harbor-idea-backlog.md)。

## 2. 名称与用途的已确认部分

| 项目 | 当前决定 | 确认范围 |
|---|---|---|
| 局内资源名称 | **工分**，暂定 | 用户明确“那先叫工分吧”；不采用需要长解释的额度／凭证包装 |
| 不采用的局内货币包装 | 钱／金币 | 用户计划可能留给未来局外消费；不由此推定局外经济已实现或规则已确定 |
| 持续规则卡大类名称 | **合约**，原称工单 | 用户明确“可以 就叫合约”；单张卡名及效果没有要求重做 |
| 工分第一个兑换物 | **合约** | 用户明确希望局内资源先用于兑换合约 |
| 付费刷新候选列表 | 进入经济初稿讨论 | 用户给出刷新费用例子；刷新流程、范围与次数还没定 |

设计名称已确认，但原型界面／代码仍可能使用“工单”等旧称，尚未实施统一替换。现有16张效果仍维护在[合约管理表](harbor-work-order-registry.md)，其文件路径保留为 `harbor-work-order-registry.md`。

工分与过关得分用途不同：得分用于阶段目标，工分用于局内兑换。后续收入与支出尚未设计，不能直接将两者按某比例兑换，也不能默认每次落箱都会产出工分。

## 3. 用户提出的经济初稿

用户原意示例：“开局有5个工分，一个合约3元，刷新列表2元之类这种。”讨论中单位统一写为**工分**，不采用“元”。

| 项目 | 示例值 | 状态 |
|---|---:|---|
| 开局持有 | 5工分 | 用户举例的讨论参数，未写入原型 |
| 兑换一份合约 | 3工分 | 同上，未作最终平衡定案 |
| 刷新一次列表 | 2工分 | 同上，列表刷新规则未定 |

用户使用“比如”表达初稿，不将5／3／2自动归档为最终数值或已获授权立即开发的完整规则。

## 4. 这组参数与上下文怎样关联

| 选择 | 算术结果 | 形成的取舍 |
|---|---|---|
| 直接兑换一份合约 | 5－3＝剩2 | 接受眼前候选，保留余额；是否能留到下一阶段仍未确定 |
| 先刷新一次再兑换 | 5－2－3＝剩0 | 花光开局资源争取更适配的合约；刷新也不承诺必有更优候选 |

这是算术与策略分析，不是已经确定的操作窗口或次数规则。尤其不能默认“兑换后仍能刷新并再买”：按当前示例余额，兑换后刷新就会变0，没有后续收入就无法再兑换。

它与现有流程的关键关联：原型目前**每阶段开始前免费三选一，选定才开始作业**。改为消耗工分后，需要明确免费获取是否被替代、候选数是否仍为三、余额能否用于后续阶段。

它与现有难度的关联：当前两个阶段目标2600／3000，移除满列奖励后无合约单阶段上限2400，必须利用合约收益。若开局刷新＋兑换后余额归零，而后续又只允许付费获取，就需要配套资源规则；但已有合约跨阶段保留，所以余额为零也不能未经验证就断言必死。应结合收入、已有合约与后续选择一起判断。

## 5. 本次归档时的停点：尚待用户回答

**优先问题（ECO-001关联ORD-004）：**

> 你希望这套工分兑换，替代现在每阶段免费的合约三选一，对吗？

这句话是Codex上一轮提出的确认问题，**用户本轮要求将问题和上下文归档，没有回答“替代”或“保留”**。

| 可能的回答 | 后续含义，均未定案 |
|---|---|
| 替代免费三选一 | 获取合约进入付费选择，需要明确各阶段资金、兑换机会和开始作业条件 |
| 免费三选一保留，工分用于额外获取 | 工分是额外构筑途径，需要明确额外获取时机、数量与候选刷新对象 |
| 采用其他混合方式 | 先由用户描述范围，再记录方案，不默认免费首张或其他补贴 |

“沿用三项候选列表”也是Codex提出的简化建议，用户尚未确认。现有免费流程仍是原型的实际行为，不能因本档使用“合约兑换”就当成已经替换。

## 6. 回答停点后再逐项讨论

1. 工分何时、通过什么方式补充；是否与落箱、阶段交付或任务有关。没有默认采用其中一种。
2. 余额是否跨阶段保留；一局结束如何处理，是否与局外资源隔离。
3. 每次展示多少份合约、每阶段可兑换几份，买后候选是否移除、补位、锁定或关闭。
4. 刷新全部候选还是部分，收费固定还是递增，能否反复刷新，以及是否继续遵循已持有不重复等现有条件。
5. 5／3／2是否先作为试玩数值，怎样与阶段难度、合约强弱及高分追求共同校准。

以上是待决问题，不是批量确认的新方案。继续遵循用户偏好逐项沟通，先回答第5节，再细化收入；不直接实现整套商店，也不默认消耗道具已进入兑换池。
