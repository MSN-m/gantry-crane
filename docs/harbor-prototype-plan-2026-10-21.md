# 港口吊装原型：三批修改与测试对照清单

工单的当前维护资料见[工单管理表](harbor-work-order-registry.md)，本清单保留实施与试玩验收记录。
日期：2026-10-21。

本文整理本轮聊天中已确认的需求与三批实施计划。它是后续修改、试玩和验收的对照依据，不代表功能已经实现。所有测试项初始均未勾选。

本轮规则取代旧原型的“双车自动补位、固定24箱必须全部装完、必须满船、无限撤销”等对应规则；旧文档与旧测试只作为历史依据。本文未规定的数值和交互细节不得视为已经确认。

## 最新规则修订（2026-10-22，phase3-v2）

- 新增已确认的“取消当前持货”：尚未放置时可送回本次货车／周转车来源，移动途中也可以。下降、提升期间锁定。完成返回、下降放回、安全提升后停在来源位置，不额外回开局原点。不计分、不触发工单、不推进成长或接力，不自动切批或结束，已落船箱子仍不可撤销。按钮位于主操作旁，并支持Esc。
- 用户明确移除满列额外加分，覆盖下方所有历史“满列＋200”记录。当前只有基础、上下同色和工单得分；不要求满载。
- 第一关两个阶段门槛由1200／1600提高到2600／3000，高分线仍8000。无工单单阶段最高2400，两个阶段都必须取得工单额外收益。
- 首阶段不提供单独无法越过2400的转色协议；已有边角专家时，第二阶段也不提供理论上限仅2760的纯转色组合。其余可行组合仍可获得转色协议。
- 工单系数、货量和已确认的镜头／吊具返回规则保持原样。记录与参数版本更新为phase3-v2；旧版本模拟数据仅作历史依据。
- 人工复核：无工单完美满载仍未达标；追加报酬等评分工单能帮助通关；末箱不再出现额外200分或将其乘入倍率。

## 第一批：装载循环与多列推进

目标：先验证选货、放行、临停和切列是否有趣。本批先用基础计分跑通流程，工单在第二批接入；临时门槛只用于测试。

### 1. 来货与切批

- [ ] 每批四辆货车，以两条车道、每道两辆的2×2方式排列，都在吊具下方、同时可选。
- [ ] 只展示当前批货物，不增加后续批次预告。
- [ ] 玩家可任意选择本批货物及吊装顺序，不必全部接收。
- [ ] 本批全部取完后切换下一批；也可手动选择“下一批”。
- [ ] 手动切批时，本批尚未取走的货物永久放行，本关不再回来。
- [ ] 已移入周转车的货物不随切批放行。

### 2. 周转车

- [ ] 提供两辆基础周转车，每辆容纳一只长箱或短箱，不堆叠。
- [ ] 周转车位于来货区靠船一侧，左右并排、独立成排，随作业位置移动。
- [ ] 只接收来自货车的货物；船上已摆好的箱子不能搬回周转车。
- [ ] 车上货物跨批、跨列保留，之后可以取出装船。
- [ ] 临停、重新吊起或周转取放不计分、不触发交付次数；正式落船才计分。

### 3. 落箱与布局锁定

- [ ] 正式落箱前可改选目标。
- [ ] 正式落船后不能撤销，也不能重新搬动、修改布局。
- [ ] 原型现有长短箱占位、三层容量与长箱等高支撑继续作为测试基础；未另行确认的新尺寸和支撑规则不加入。

### 4. 多列与来货额度

- [ ] 首轮做两列，从船尾开始依次推进。
- [ ] 每列独立提供六批、每批四辆，共24辆；两列最多48辆。
- [ ] 每列独立计算得分和最低门槛，后一列要求更高。
- [ ] 前列超额分不能抵扣后一列门槛，各列实际得分最终累加为整船总分。
- [ ] 本列达标后解锁手动切列，玩家可继续装载争取高分。
- [ ] 切列后旧列布局封存，不能返回修改。
- [ ] 切列时，当前批未取货及本列尚未出现的所有批次永久放弃。
- [ ] 两辆周转车及其货物跟随进入下一列。

### 5. 基础计分与结束

| 项目 | 首轮测试配置 |
|---|---|
| 短箱基础分 | 50分／半格 |
| 长箱基础分 | 100分／两半格 |
| 上下同色奖励 | 每处半格邻接＋25分 |
| 每列装满奖励 | 已于2026-10-22移除，不额外加分 |
| 每列门槛、整船高分线 | 当前2600／3000，高分线8000；无工单单列最高2400 |

- [ ] 不要求装满或接收全部货物才可结算。
- [ ] 最后一批来货处理完后，仍可装载周转车上的货物。
- [ ] 任何准备结束挑战的情况，只要周转车有货，就先提醒，不直接清空或判定最终结果。
- [ ] 提醒提供“返回继续摆放”与“放弃剩余货物并结算”。
- [ ] 返回只允许在当前列操作，不解锁旧列，也不允许搬动已落船箱子；无合法落位时仍可返回查看。
- [ ] 切批与切列不属于结束挑战，周转车正常带货保留。
- [ ] 本列来货耗尽、周转货物已装船或主动放弃后，若仍未达标，本次挑战结束。
- [ ] 失败展示已完成列数、累计总分及本列分数差额。
- [ ] 全部列达标为“达标交付”；全部列达标且总分达到高分线为“高分交付”。
- [ ] 高分评价不额外要求满载、零放行或把所有周转货物装上船。

### 本批建议测试路线

| 场景 | 操作 | 预期 |
|---|---|---|
| 部分接货 | 本批取两箱，手动下一批 | 其余两箱永久离开，新批正常到场 |
| 跨批留货 | 将一箱放周转车后切批 | 周转货物保留，之后装船才得分 |
| 跨列留货 | 达标后带货切列 | 旧列锁定，周转货物可在新列装载 |
| 提前切列 | 仍有未出现批次时切列 | 放弃本列余货，不减少新列独立额度 |
| 结束返回 | 周转车有货时尝试结束 | 弹提醒，可返回；返回不丢货、不结算 |
| 未达标结束 | 耗尽机会并放弃周转余货 | 失败且正确显示差额 |

## 第二批：货主与工单构筑

目标：验证工单能否改变取货、装载顺序和空间选择，且形成跨列收益。

### 实现记录（2026-10-21）

- 两家货主、每列三选一、卡片详情及拖动排序已接入。两家货主专属版本分别成单，共九类／16张工单；同名不重复，候选分为三种机制。
- 用户试玩调整：移除场景右侧“船舶区／来货区”按钮，改为鼠标／单指拖动画面；轻点实物仍选位并自动对准。已验证拖动不误选、视野边界、触控取消与抓放锁定。
- 最新视角要求取代上条平移方案：默认朝向固定，拖动仅改变镜头观察角度，松手保持；点击目标后镜头随实际X／Y移动，角度不复原。切批／切列保留观察角度，新一局恢复默认，仍保留小幅手势阈值与抓放锁定。
- 视角范围进一步收紧：上下限定为全部货车、船舱与少量海水，左右限定为当前及相邻两列。边界随作业位置／屏幕调整；增加平滑跟随、边缘减速，角度因作业移动超出新边界时平滑修正，不强制回默认。
- 后续试玩修订上述保持规则：查看时松手保持角度；每次抓取、临停或落箱并完成提升后，视角平滑返回当前作业位置的中心朝向，吊具不返回其他位置。为减少晕动，取消附加摇摆，X／Y缓起缓停且移动阶段不自动转头，到位后再做角度限位。
- 最新用户反馈优先改用更高的默认俯视取景，尽量同时覆盖船体和车道。原型相机高度由300提高至520，横向取景范围扩到船体，保留小幅转头、作业后回正和低晃动移动；远处货主标签采用最小字号与单字简称。
- 最新截图要求覆盖上述拖动规则：高度微调至480，暂时关闭镜头拖拽；保留轻点选位、作业自动跟随与工单卡拖动排序。鼠标及触控回归通过，可对照截图试玩确认取景。
- 最新返回规则覆盖“当前作业位置回正”：每次移动或抓放结束，镜头平滑返回开局原点，保持观察角度；吊具与选位不返回原点。镜头仍暂时禁止拖拽。
- 用户纠正上条：仅放置集装箱并升回安全高度后，镜头、吊具一起回开局原点；单独移动、吊起货箱均不返回或重置角度。落船与周转车临停都属于放置，返回过程中锁定新操作。
- 旧列布局参与后续适用工单，历史分数不重算。新工单只从取得后开始计分与成长。
- 临时参数：优先提货每箱20；长期客户初始20、成长5；接力每档10；边角60；追加25；倍率1.5；乘法四舍五入。列门槛1200／1600、高分线3800暂不变。
- 每列基础货单两家货主各12箱。已有工单只关注同一货主时，本列适度支持该货主至14箱，不重抽颜色、尺寸或批次。
- 满列200计入本次倍率之前；封顶追加计算采用当前转色协议，但不修改此前已得同色分。
- 无直接计分效果的转色协议不能被复核；复核左侧不适用时显示原因。已有工单无可复核效果时，三选一不提供复核。
- 规则检查：check-orders.cjs覆盖全部效果、100种种子的两次选卡和240种有序双卡组合的两列装载；第一批check.cjs继续通过。
- 浏览器检查覆盖选卡、详情、拖动及按钮排序、成长只加一次、旧列分数封存、场景操作、结束提醒与320px布局，无页面脚本错误。
- 以下勾选项仍留给用户逐项试玩，不用程序检查替代人工体验验收。

### 1. 货主与获取规则

- [ ] 首轮两家货主：电力设备公司、医疗用品公司，名称暂为占位。
- [ ] 货主不自带能力，由工单赋予效果；没有相关工单时照常按基础规则计分。
- [ ] 两家货主均可拥有四色及长短箱，不与某种颜色、尺寸固定绑定。
- [ ] 首轮货单人工安排，为不同工单提供可验证的机会。
- [ ] 每列开始前提供一次工单三选一，包括第一列。
- [ ] 已持有的同名工单不再进入候选；首轮不做重复获取或升级。
- [ ] 候选与本局可能出现的货物匹配，不保证眼前立即触发。
- [ ] 允许所选工单影响接下来一列的货单配置；具体配置算法待实现时明确。
- [ ] 已有工单及成长进度跨列保留；两列原型的两张工单共同生效，暂不设额外槽位限制。

### 2. 工单池与逐张验收

奖励、成长量与倍率均待第三批校准，表中规则已确认。

| 工单 | 确认规则 | 测试 |
|---|---|---|
| 优先提货 | 每次正式落船后，整船每只上方无遮挡的指定货主箱子分别奖励；落下其他货主也会触发。被遮挡者停止后续加分，历史收益不扣回；长箱任一半被压即不满足 | [ ] |
| 长期客户 | 每正式交付一只指定货主箱子，先按当前奖励发分，再提高后续奖励；成长跨列保留 | [ ] |
| 长短接力 | 按正式落船顺序，长短交替则奖励递增，同尺寸则本次接力奖励为零并重置；下一次成功交替从第一档开始。临停、切批、切列不打断状态 | [ ] |
| 边角专家 | 短箱落下后使完整箱位左右高度相同，给予固定奖励，不附带成长；长箱齐平不触发 | [ ] |
| 封顶交付 | 完整箱位左右首次都达到三层时，将其中全部箱子的基础分和同色奖励额外结算一次；不包括其他工单收益，每箱位只触发一次 | [ ] |
| 转色协议 | 红蓝、红黄、红绿、蓝黄、蓝绿、黄绿分别成单；配对颜色在同色计分中互认，实际颜色不变。封顶追加计算也适用；多张协议不传递合并 | [ ] |
| 追加报酬 | 每次正式落船固定加分，长短箱相同；临停取放不触发 | [ ] |
| 加急奖金 | 轮到本工单时，将本次已累计得分乘固定倍率，立即兑现；不乘当前列或整船历史总分 | [ ] |
| 复核奖励 | 左侧相邻工单的计分效果额外执行一次，须满足原条件；最左侧无效果。不重复成长，长期客户使用本次正常触发的奖励值；左侧为倍率则再乘一次 | [ ] |

工单池共九类，其中转色协议六个固定版本。第二批测试中，优先提货与长期客户分别按电／医拆成独立版本，共16张；“配套运输”本轮不加入。

### 3. 结算顺序、跨列与重复触发

- [ ] 先计算本次基础分与摆放奖励，再将工单从左到右依次处理，本次收益计入当前列。
- [ ] 玩家可调整工单顺序；已获得的分数不因排序而重算。
- [ ] 旧列布局虽不可修改，仍参与适用工单的后续触发；新收益计入当前列，不回改旧列已结算分。
- [ ] 新工单可以利用已有布局，从后续落箱起生效，不追溯历史得分或补成长次数。
- [ ] 一次真实落船只产生一次落箱事件；额外计分仅重复指定效果，不重新启动整条结算。
- [ ] 额外计分不增加交付箱数，不增加成长次数，也不重新触发封顶里程碑。
- [ ] 转色协议作为同色判定规则参与基础计分和封顶计分，不能因卡片摆在后方而遗漏其判定效果。

### 4. 工单表现

- [ ] 工单贴在驾驶舱下沿、主操作按钮上方，横向排列。
- [ ] 点击可看完整说明，拖动可调整顺序，结算从左到右亮起。
- [ ] 箱子保留颜色、尺寸、货主等基础信息，不添加工单专属小标。
- [ ] 工单即时收益清楚可辨，不使用已被否定的“预计最终奖励解锁门槛”方式。

### 本批建议组合测试

| 场景 | 预期 |

| 复核长期客户 | 奖励重复，成长仅一次 |
| 复核加急奖金 | 再乘一次本次倍率，不修改历史总分 |
| 红蓝协议与蓝绿协议同时存在 | 红蓝、蓝绿有效，红绿仍不互认 |
| 短箱补齐并同时封顶 | 分别检查边角、封顶的合法触发，不重复交付事件 |

## 实现前或体验时仍需收敛的细节

以下是原先需要收敛的细节与当前测试口径。实现中的临时配置仍可根据试玩调整，不等同于最终数值定案。

| 细节 | 当前测试口径 |
|---|---|
| 自动换批与切换边界 | 吊具空载且完成提升后换批；持货、移动或抓放期间禁切换 |
| 来货耗尽但已达标且有周转货 | 提供进入下一列／留在本列，周转货可跨列 |
| 货主专属版本 | 优先提货、长期客户分别绑定电／医，不在选卡后另选货主 |
| 无直接计分效果的复核 | 显示“左侧无可重复效果”；无适用已持有卡时不提供复核候选 |
| 排序与基础计分顺序 | 移动、抓放、计分表现期间禁排序；基础与同色后按卡序处理，满列无额外奖励 |
| 新转色协议的历史口径 | 历史分数不重算；新落箱邻接和封顶新发奖励按当前协议判断 |
| 各工单参数、两列目标及高分线 | 已有临时参数，第三批结合试玩统一校准 |
