## 操作与装载循环

- 最新取景按参考截图调整为固定高位俯视，相机投影高度为480（原型空间单位），同时覆盖船舱、四辆来货车、双周转车与少量海水。远处货主标签设最小字号，窄箱使用单字货主简称。
- “船舶区／来货区”按钮已移除。暂时关闭鼠标和单指拖动镜头；轻点实物选择及工单卡拖动排序仍可用。
- 镜头跟随吊具，保持原朝向。仅成功放置集装箱（落船或临停周转车）并升回安全高度后，吊具与镜头一起平滑返回开局原点（X=0、Y=52），清空选位。单独移动、吊起货箱或失败的放置均不触发返回；返回期间锁定新选位，抵达后继续作业。
- 超过8px的滑动不触发选位，小幅手指抖动仍视为轻点。抓放及返回期间锁定新选位，取消手势后不会残留拖动状态。沿用X／Y同步移动，不强制先走某一轴。
- 默认高位取景适配船体、车道和少量海水；镜头跟随作业位置移动，保持朝向，放置完成后与吊具一起返回原点。
- 镜头拖动相关的角度与边缘缓动逻辑暂不启用。作业移动导致角度超出新边界时平滑限位；开启减少动态效果时取消缓动。
- 为减少晕动，去掉附加吊具摇摆，X／Y自动移动与放置后的返回采用缓起缓停；作业期间不自动转头。
- 触控专项检查：`check-pan-browser.cjs`，环境同浏览器检查，覆盖手指拖动、取消、轻微抖动点击和抓放锁定；浏览器触控仿真不等同于真实手机手感验证。
- 点击场景中的四辆来货车、两辆周转车或船上箱位，自动移动后手动确认抓放。
- 四车2×2排列；每列6批。取空一辆不补位，整批取完并完成抓放后换批；也可手动下一批，永久放行未取货。
- 两辆周转车位于来货区靠船一侧，每辆停一只长箱或短箱，不堆叠，跨批跨列保留。临停取放不计分、不成长。
- 正式落船后不可撤销或搬回。短箱可点左右半位，长箱需等高支撑，最多三层。
- 吊起后、放置前，主操作旁显示“取消 · 放回原A车／原周转车1”等来源提示，或按Esc。支持闲置持货及移动途中取消；下降、提升和取消动画中禁用。吊具送回本次来源，下降恢复货物，再升至安全高度，镜头随之停在来源位置，不继续回开局原点。
- 取消不计分，不触发任何工单、成长、接力或封顶，也不自动切批／结束。周转车取出的箱子取消后回到该周转车，不回更早的来货车；正式落船仍不可撤销。
- 两列独立达标；第一列达标后可手动切列，永久放弃本列余下来货，旧布局封存。
- 结束前周转车有货时，可返回当前列摆放，或主动放弃后结算。
- 只展示当前批来货；每局、每列受控随机，开局生成后固定，不因放行而重抽。
- 键盘辅助：A/B/C/D选来货，Q/W选周转车，1—6选船位，空格确认，Esc取消当前持货并放回来源。手机直接点击为主要操作。

## 货主与选工单

- 箱面以“红·电”“蓝·医”等标识颜色和货主；电为电力设备公司，医为医疗用品公司。尺寸由实体长短及选中提示表达。
- 货主不自带能力，只有对应工单提供收益；不引入用电、冷藏、危险品等装载限制。
- 每列开始前，三选一获得一张工单。旧工单与成长保留，两列共两张，不额外设槽位上限。
- 同名不重复；货主专属工单按固定货主拆成独立版本，转色协议按固定双色拆分，共16张。
- 三个候选尽量覆盖三种不同机制；复核仅在已有可复核工单时出现。第二列会给已有路线提供一项搭配候选，保留另外选择。
- 基础货单两家货主各12箱，均有各色与长短箱。只持有同一货主专精时，本列适度支持该货主到14箱；仅调整货主分配，不重抽颜色、尺寸、批次顺序或货量。

## 工单位置与结算

- 工单贴在驾驶舱下沿、主操作按钮上方。点击看规则，左右拖动调整顺序；详情内也可使用左右按钮排序。
- 抓放、移动或工单结算表现期间不允许排序。排序不改历史分数，下一次落箱生效。
- 先算本次基础分与同色奖励，再从左到右执行工单，分数立即计入当前列。
- 工单逐张亮起，显示本次触发与收益。箱子不加工单专属小标。
- 转色协议是持续判定规则，不因位置在计分卡之后而失效；复核放在其右侧没有可重复的计分效果。
- 旧列箱子继续参与适用工单，新增收益计入当前列；新工单可以利用旧布局，但不追算历史得分与成长。
- 计分使用逐次记录；新获得转色协议、调整卡序或进入新列，不会重算以前的得分。
- 额外计分只重复指定效果，不制造落箱事件；不重复交付次数、成长或封顶标记。

## 第三批表现与记录

- 每次落船显示基础、同色奖励，再从左到右展示工单加分、成长与倍率的计算过程。计分立即兑现，最多520ms的卡片表现与提升动画重叠；没有新增等待按钮。
- 工单详情保留上次落船的触发结果，结算浮层结束后仍可查看。复核不会显示额外成长；只有实际加分的卡片亮起。
- 头部显示本列目标、整船累计分、当前及后续批次数。切批提示永久放行数；手动切列先确认余货放行和旧布局封存，可取消。
- 结算展示逐列得分、前台作业用时、装载率、交付／放行箱数、周转次数、主动切列批次，以及种子与参数版本。选卡、查看工单、结算弹窗及后台时间不计入作业用时。
- 结算点击“导出本局记录”下载JSON，包含参数快照、逐列统计、工单获取／排序与取放事件。仅保存在本局内存中，不自动上传；重新开始前可导出。
- 配置入口为 `config.js`；程序与工单文案共用参数。比例与投影未在第三批调整。

## 当前测试参数（phase3-v2）

| 项目 | 数值／口径 |
|---|---|
| 基础分 | 短箱50，长箱100 |
| 同色 | 上下相邻每半格＋25，适用转色协议 |
| 满列 | 不额外加分（2026-10-22移除） |
| 优先提货·电／医 | 每次落船，整船每只对应货主无遮挡箱＋20；长箱两侧均无遮挡，只计一只 |
| 长期客户·电／医 | 初始＋20；每次匹配交付先发分，再成长＋5，跨列保留 |
| 长短接力 | 首箱0，连续交替10、20、30…；同尺寸0并重置，跨批跨列保留 |
| 边角专家 | 短箱落下使左右齐平，＋60 |
| 封顶交付 | 左右首次都到三层，额外结算箱位当前基础分＋同色奖励一次；同色按当前有效协议判断，已得分不重算 |
| 转色协议 | 六张固定双色版本；不改变实际颜色，不传递合并 |
| 追加报酬 | 每次正式落船＋25 |
| 加急奖金 | 本次已累计分×1.5，每次乘法四舍五入到整数 |
| 复核奖励 | 左侧相邻可重复计分效果再执行一次；长期客户重复本次奖励值而不重复成长，倍率再乘一次 |
| 列门槛 | 第一列2600、第二列3000，独立计算 |
| 整船高分线 | 8000；必须先通过全部列 |

2026-10-22：按用户要求移除满列奖励，门槛从1200／1600提高到2600／3000。无工单单列上限为36半格×50＋24处上下邻接×25＝2400，两阶段都必须取得额外工单收益，旧列超额分不能抵扣本列门槛。高分线仍为8000。首列不提供单独无法越过2400的转色协议；第二列若只有边角专家，也不提供会使理论上限仍低于3000的转色组合。转色协议保留在其他可行的第二列候选中，工单系数未调整。

当前四种策略各200局：达标即交付137局通过，持续普通装载136局通过，单路线和组合规划均200局通过；后三者总分中位数分别7703／10200／9313，高分次数85／149／199。这里的普通策略仍持有工单，只是不主动优化效果；模拟不是真人通关率。完整数据见 `balance-phase-three-results.json`，复现 `node prototypes/harbor-operator/balance-phase-three.cjs 200`。旧phase3-v1数据存入 `balance-phase-three-results-phase3-v1.json`，不作为当前难度证据。
